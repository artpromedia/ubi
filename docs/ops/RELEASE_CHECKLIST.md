# Pilot release checklist — SLO targets and final evidence

Two sections, both honest about what is and isn't decided or proven yet:
§1 names the metrics the launch pack asks for and leaves every threshold
for the owner to set (no invented passing number); §2 is the final-evidence
checklist with each item marked by what actually exists right now.

## 1. SLO targets (owner to set every threshold)

These metric names match the ones already used in
`docs/marketplace/ROLLOUT.md` §"Staged activation" and
`docs/marketplace/RUNBOOK.md` §"Health signals" — this list does not invent
parallel terminology, it turns those into named targets with numbers still
missing.

| Metric                        | Definition                                                                                                                        | Target           | Where it's measured today                                                                                                                                                                                                                                                                                                             |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Publish → first-offer latency | Time from a rider publishing a request to the first bid/offer reaching them.                                                      | **OWNER TO SET** | Observable per `ROLLOUT.md` step 2; no dashboard/alert threshold configured yet.                                                                                                                                                                                                                                                      |
| Publish → award latency       | Time from publish to a confirmed award.                                                                                           | **OWNER TO SET** | Same.                                                                                                                                                                                                                                                                                                                                 |
| Funding-failure rate          | Share of selections where funding authorization (`mp-funding.ts`) fails or is rejected.                                           | **OWNER TO SET** | `mp.award_attempts` is queryable (per `ROLLOUT.md`/G11 admin note); no alert threshold.                                                                                                                                                                                                                                               |
| Hold-release lag              | Time between a hold becoming releasable (cancel/expiry/settlement) and the release actually posting.                              | **OWNER TO SET** | `mp_commission_holds` age is a named RUNBOOK health signal; no threshold.                                                                                                                                                                                                                                                             |
| Pending-saga age              | Age of an award stuck in `award_pending` / `capture_pending`, or a `mp.reservation_recovery` backlog entry.                       | **OWNER TO SET** | Named RUNBOOK health signal ("`mp.awards` age in `pending`"); sweep retries automatically, but no alert threshold for "page a human" exists.                                                                                                                                                                                          |
| Location freshness            | Age/accuracy of the last driver position used for a matching or bidding decision.                                                 | **OWNER TO SET** | Server-side staleness/accuracy gates exist per policy config (`stationary` block in `ROLLOUT.md`); **no client telemetry reaches the server at all yet** (G05 — driver-mobile sends a bodyless parked ping only). This metric cannot be measured meaningfully until G05 closes; do not set a target that implies it can be met today. |
| Queue-window miss rate        | Share of queued-next pickups that miss `queue.pickupWindowToleranceSec` and trigger the fee-free exit (`mp.queue.window_missed`). | **OWNER TO SET** | Emitted per RUNBOOK; no aggregate rate/alert configured. Also gated by G07 (rider queue projection is fixture-only) for the rider-visible half of this.                                                                                                                                                                               |
| Notification-failure rate     | Share of marketplace `mp.*` events that should have produced a push notification but didn't.                                      | **OWNER TO SET** | **Cannot be measured at all today** — G10: notification-service has no `mp.*` subscription; every handler is a logging stub. This target is meaningless until G10 closes; recorded as blocked, not as an unset number to fill in casually.                                                                                            |
| Cancellation rate             | Rider/driver cancellations as a share of published requests, split pre-service vs. after-assignment.                              | **OWNER TO SET** | Named in `ROLLOUT.md` step 2; abuse-pattern detection beyond a per-incident fee does not exist yet (A06).                                                                                                                                                                                                                             |

None of these have a passing threshold in this repository. Setting one is a
product/ops decision (acceptable latency, acceptable failure rate for a
pilot city, etc.), not something to infer from test fixtures — inventing a
number here would violate the same rule that keeps CI honest.

## 2. Final-evidence checklist

| Item                                                                                               | Status                 | Exact dependency                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Both-platform ride recordings (real device run, both apps, both platforms)                         | **PENDING-DEPENDENCY** | No native iOS/Android project exists for either RN app yet (G06); no signing credentials or macOS/Android device runner in this environment. See `docs/ops/NATIVE_RELEASE.md` §1–§5 for the exact scaffold command, identities, and secrets needed before this can even be attempted.                                                                                                                                                                                    |
| Concurrency/financial test output (competing spends, duplicate authorize, exactly-once settlement) | **PENDING-DEPENDENCY** | Unit/DB-level ledger tests pass today (`unit-services` job, payment-service matrix entry — deferred double-entry trigger, row locks, idempotency keys). Cross-service concurrency under real load has no executable evidence yet (`GAP_REGISTER.md` V02); needs the load-test infra named in `docs/ops/CI_EVIDENCE.md`'s "performance" gap.                                                                                                                              |
| No skipped mandatory checks                                                                        | **DONE**               | `test-status` (test.yml) and `ci-success` (ci.yml) both treat a _failed or cancelled_ unit job as failure; a legitimately-skipped job (path filter didn't match) is not conflated with a passing one. `rn-native.yml`'s guarded jobs are not required checks and never claim device coverage when they skip a build (fixed this pass — see `docs/ops/CI_EVIDENCE.md`'s `ci-success` note for the one bug found and fixed: `rn-mobile`'s result is now actually checked). |
| Restore-drill output (measured RPO/RTO)                                                            | **PENDING-DEPENDENCY** | `docs/deploy/HETZNER_PILOT.md` §6 gives the exact restore procedure and states RPO/RTO as measure-and-fill; no server exists in this environment to run the drill against. Needs a provisioned Hetzner host + an off-host encrypted backup target (§6 also names this as unprovisioned — `BACKUP_S3_BUCKET` is unwired).                                                                                                                                                 |
| Operational ownership (on-call, incident response named)                                           | **PENDING-DEPENDENCY** | `docs/marketplace/RUNBOOK.md` names the technical procedures; no named human/team owner or on-call rotation exists in this repository — that's an organizational decision, not a code or doc gap this pass can close.                                                                                                                                                                                                                                                    |
| Unresolved exclusions (what stays out of the pilot, stated to participants)                        | **DONE**               | `docs/launch/GAP_REGISTER.md`'s "Smallest complete stationary-ride pilot" section already states these plainly: no push notifications (WS + refresh only), single-host deployment (failure domain documented in `docs/deploy/HETZNER_PILOT.md` §7), delivery/queued jobs/AI unavailable and unadvertised.                                                                                                                                                                |

**Nothing in this checklist, or in any document this pass produced, claims
the platform is launch-ready or device-verified.** Every PENDING-DEPENDENCY
row names the exact external thing blocking it (a runner, a credential, a
server, an organizational decision) rather than a vague "more work needed".
