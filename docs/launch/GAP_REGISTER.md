# UBI launch gap register

Audit baseline: `732ff85855d54adc032e83b00a1e84d7afcaa955` (master, 2026-09-21).
Every finding below was re-verified at HEAD on `claude/cool-pascal-gvw628`
before being recorded; where the audit's pointer was imprecise, the corrected
evidence is given. This register is the C01 deliverable: each launch-visible
flow is either backed by a real, supported implementation or deliberately
gated, and every blocker carries a testable closure condition.

Severity: P0 blocks a money-moving pilot; P1 blocks the affected feature;
P2 improves operations or expansion. Classification matters: a **confirmed
defect** is wrong behavior in code that runs; a **missing feature** is an
absent or placeholder surface; an **unverified risk** is something no evidence
proves safe or broken.

## Smallest complete stationary-ride pilot

One city, rides only, foregrounded apps, wallet + cash:

1. **Flags:** marketplace enabled for the pilot city only; queued next job OFF (until C06); delivery OFF (until C07); AI adapters OFF (C10). Unconfigured markets keep failing closed.
2. **Money:** C02 landed — wallet fares reserved at selection, consumed exactly once at completion, released on cancellation/expiry; cash labeled unsecured; every other method hidden and failing closed server-side. 10% commission reserve/capture-once unchanged.
3. **Trust:** C03 landed — production refuses to start without the internal identity secret; forged-header, cross-tenant and route-inventory tests in CI.
4. **Lifecycle:** C04 landed — driver-cancel terminal path with policy-versioned fee/commission reversal exactly once; repair job for stranded records; no silent re-search without requester consent.
5. **Execution:** C05 — rider/driver auth, PIN, in-trip, complete, receipt implemented in RN against real endpoints; position ingest wired with server-side gates. Device-run acceptance (two real accounts, both platforms) is an explicit external dependency: signing credentials + device runners.
6. **Operations:** admin monitor + policies pages, RUNBOOK procedures for stuck sagas and reservation recovery, a named on-call owner.
7. **Known pilot limitations, stated to participants:** no push notifications (WS + refresh only), single-host deployment (documented failure domain), delivery/queued jobs/AI unavailable and unadvertised.
